What a mesh is

Every asset your pipeline will ever produce, whether Tripo generated it or a script built it, reaches Bevy as the same small data structure. Learn to read it and you can inspect anything.

The win: by the end you will run one command on a model file and say what every line of the output means.

A mesh is a table and a list

The file Bevy loads is glTF (a .glb is the same thing packed into one binary file). Inside it, a mesh is a list of primitives, and a primitive is three things:1

  1. A vertex table. Each row is one vertex. Each column is an attribute.
  2. An index list. Integers, read three at a time. Each triple names three rows of the table, and those three vertices are one triangle.
  3. A reference to one material, which says how the surface responds to light.

That is the whole shape of it. A game model with a million triangles is this same structure with a longer table.

Three columns matter first

glTF nameArtists call itTypeWhat it holds
POSITIONvertex position3 floatsWhere the vertex is, in metres.2
NORMALnormal3 floatsA unit vector: the direction the surface faces at this vertex. Lighting is computed from it.3
TEXCOORD_0UV2 floatsA point on a 2D image. It says which part of a texture lands on this vertex.4

Position gives the silhouette. The normal gives the shading. The UV gives the paint. Bevy's own documentation says a mesh needs normals and UVs to render correctly with its standard material.3

The consequence that surprises programmers

A vertex is a whole row, not a point in space. If two triangles meet at the same position but need a different normal or a different UV there, that is two rows. The Khronos guidelines put it this way: vertices are split on export if they contain more than one of each type of mesh data.4

Predict before you read on. A cube has 8 corners. Each face must be lit as a flat face, so each face needs its own normal. How many rows does the vertex table have?

Answer

24. Every corner touches three faces, and each face wants a different normal there, so each corner is stored three times: 8 × 3, or equally 6 faces × 4 corners. A sharp edge always costs vertices. A smooth surface shares them.

This is why "how many triangles" and "how many vertices" are different questions, and why an asset's cost depends on its edges and its UV layout as well as its shape.

Do it: read two real files

Two models kept from the first kiln attempt are enough. From the repository root:

python3 learn/assets/glb_inspect.py learn/specimens/crate.glb
python3 learn/assets/glb_inspect.py learn/specimens/boulder_1.glb

Before you run them, write down three guesses.

  1. The crate is drawn in two flat colours. How many primitives will it have?
  2. The boulder has a painted texture. Which of the two files will have a TEXCOORD_0 column?
  3. Which will have more vertices than triangles: the hard-edged crate or the rounded boulder?
What you should see, and why
  1. Two primitives. A primitive has exactly one material, so two materials force two primitives. In Bevy each primitive arrives as its own mesh with its own material.5
  2. Only the boulder. The crate has no texture, so nothing needs to say where on an image a vertex sits.
  3. The crate: 144 vertices for 96 triangles in its frame. The boulder has 115 vertices for 136 triangles. A closed, fully shared surface of 136 triangles would need about 70; the rest are splits, from sharp edges or from the cuts in its UV layout. The file does not say which, and a later lesson shows how to find out.

Why this is the first thing to know

Tripo's API documents a face_limit option of up to 2,000,000 faces, and a quad option that forces the output format to FBX.6 Until today those were words. Now the first is a row count you can compare with a budget, and a generated file is something you can open and measure before you trust it. Every later topic in this course (UV layout, normal maps, baking, levels of detail) is an operation on this table.

Read next: the Meshes page of the Khronos glTF Tutorial. It is short, written by the people who own the format, and shows the same structure as raw JSON.

Check yourself

Answer from memory, without scrolling up. The first click counts.

1. A hard-edged cube with no texture is exported. How many vertices does the file hold?

Each corner needs three different normals, one per face it touches, and a row holds one normal. Thirty-six would be the count with no index list at all.

2. A file has positions and UVs but no normals. What does the glTF spec require of the engine?

The spec says that when normals are not specified, client implementations must calculate flat normals. The asset loads, and every triangle looks faceted: a defect no error message reports.

3. One mesh uses three materials. How many primitives does it have?

A primitive refers to a single material. More materials means more primitives, each drawn separately.

4. Two vertices share a position and a normal, yet are separate rows. What differs?

A row is the whole set of attributes. Where a texture layout is cut, the same point on the model sits at two places on the image, so it needs two rows.

Ask your teacher. Anything unclear, or anything you want pushed further (why triangles and not quads, what a normal map has to do with normals, what the index list buys), ask in the Claude Code session. That is what it is for.
